From Code to Cloud

How the books travel from source code to your browser

The Two Deployment Paths

The books are built. Now how do they reach readers? This project has two paths to the web — one automated, one containerized.

🚀
GitHub Pages

Free, automatic. Every push to the main branch triggers a workflow that builds and publishes the books. Zero server maintenance.

🐳
Docker + nginx

Self-hosted. Package everything into a container and run it anywhere — your own server, a cloud provider, behind a corporate firewall.

The GitHub Actions Workflow

When a developer pushes code to the main branch, a fully automated pipeline takes over. GitHub Actions orchestrates every step — no human intervention required.

1

Code is pushed to the main branch

2

GitHub Actions checks out the code and installs Rust

3

It caches dependencies so builds are faster next time

4

It installs mdbook and mdbook-mermaid

5

It runs cargo xtask deploy (same build process, outputs to docs/)

6

GitHub Pages publishes docs/ as a live website

💡
Key Insight

The deployment uses the exact same xtask tool as local development. The only difference is the output folder: site/ for local preview, docs/ for GitHub Pages. Same code, different destination.

The Docker Recipe

The second deployment path uses Docker to package the books into a self-contained unit. The key technique is a multi-stage build — one stage builds the books, and a second, much smaller stage serves them.

Dockerfile FROM rust:1-slim-bookworm AS builder RUN cargo install mdbook mdbook-mermaid COPY . /src WORKDIR /src RUN cargo xtask build FROM nginxinc/nginx-unprivileged:1.27-alpine COPY --from=builder /src/site/ /usr/share/nginx/html/ EXPOSE 8080
Plain English
FROM rust:1-slim-bookworm AS builder — Start with a pre-made box that has Rust installed. Call this stage 'builder' — it will be thrown away later
RUN cargo install mdbook mdbook-mermaid — Install the book-building tools inside the box
COPY . /src — Copy all the book source files into the box
WORKDIR /src — Move into the source directory
RUN cargo xtask build — Build all 7 books into HTML — the same command developers run locally
FROM nginxinc/nginx-unprivileged:1.27-alpine — Start a NEW, tiny box with only a web server. The builder box (with Rust, compilers, etc.) is discarded
COPY --from=builder /src/site/ /usr/share/nginx/html/ — Grab just the finished websites from the builder box and place them where nginx can serve them
EXPOSE 8080 — Tell Docker this container listens on port 8080 for web traffic

Why Two Stages?

ℹ️
Multi-Stage Builds

The builder stage includes Rust, cargo, mdbook, and all compilation tools — over 1 GB of software. The final stage is just nginx + static HTML files — under 50 MB. Multi-stage builds keep the final image small and secure by throwing away everything that was only needed for building.

The final nginx stage is not just small — it is also hardened for production. Here are the three key security and performance features baked into the configuration:

🔐
Security Headers

X-Content-Type-Options, X-Frame-Options, and Referrer-Policy headers protect against common web attacks

👤
Unprivileged User

The container runs as a non-root user (uid 101) — even if someone breaks in, they cannot harm the system

⚡
Asset Caching

Static files are cached for 1 day, with gzip compression for CSS, JS, and SVG — faster page loads for readers
