More Than Just Text

Most programming tutorials are walls of text with occasional code blocks. These books pack interactive tools into every chapter.

📊
Mermaid Diagrams

Visualize complex flows — like how async code executes or how data moves between components. Written as text, rendered as beautiful SVGs.

▶️
Editable Playgrounds

Code examples you can edit and run directly in the browser. Change a variable, hit Run, see what happens. No setup required.

🎯
Difficulty Indicators

Every chapter is tagged with difficulty: green for easy, yellow for intermediate, red for hard. You always know what you are getting into.

🔍
Full-Text Search

Search across all chapters in a book instantly. Forgot where ownership was explained? Search and jump right there.

How Diagrams Are Born

The books use Mermaid to create diagrams. Instead of drawing in an image editor, you write plain text — and a preprocessor converts it into a clean SVG diagram during the build. Here is a real example from the async book showing how futures are polled:

async-book ch02 — Mermaid diagram sequenceDiagram participant E as Executor participant F as Future (Task) participant OS as Operating System participant R as Reactor (Runtime) E->>F: Calls poll(cx) F->>OS: Syscall (e.g., read TCP socket) OS-->>F: Returns Error: Not Ready F-->>E: Returns Poll::Pending
Plain English
sequenceDiagram — Draw a timeline showing messages flowing between actors, from top to bottom
participant E as Executor — Create an actor called "Executor" (the thing that runs tasks) — label it "E" for short
participant F as Future (Task) — Create an actor called "Future" — a task that will eventually produce a result
participant OS as Operating System — The operating system — the software that manages your computer hardware
participant R as Reactor (Runtime) — The reactor — a listener that watches for events (like data arriving from the network)
E->>F: Calls poll(cx) — Solid arrow from Executor to Future: "Hey, are you done yet?"
F->>OS: Syscall — Future asks the operating system to check the network socket
OS-->>F: Returns Error: Not Ready — Dashed arrow back: "Nope, no data yet"
F-->>E: Returns Poll::Pending — Future tells Executor: "Not ready — I will let you know when I am"

The Book Configuration

Every book in the project has a book.toml file — a TOML configuration that tells mdbook how to build it. Here is a simplified version from the async book:

book.toml [book] title = "Async Rust" authors = ["Rust Training Team"] language = "en" [preprocessor.mermaid] command = "mdbook-mermaid" [output.html] default-theme = "light" preferred-dark-theme = "ayu"
Plain English
[book] — Basic book information — title, authors, and language
title = "Async Rust" — The name shown in the browser tab and page header
authors = ["Rust Training Team"] — Who wrote it — shown in the book metadata
language = "en" — Written in English — affects things like search behavior and text direction
[preprocessor.mermaid] — Before building, run the Mermaid preprocessor to convert diagram text into images
command = "mdbook-mermaid" — The actual program to run for Mermaid processing
[output.html] — Settings for the HTML output
default-theme = "light" — Start with a light background (readers can switch to dark mode)
preferred-dark-theme = "ayu" — When readers choose dark mode, use the "Ayu" color scheme — a popular warm-toned dark theme

The Curriculum Architecture

Each book follows a consistent three-part structure. This is not random — it mirrors how experts actually learn: start with what you know, go deep on the hard parts, then prove you can build something real.

1
Part I: Foundations

The basics, connecting Rust concepts to what you already know

2
Part II: Deep Dives

Focused exploration of major topics (concurrency, async, systems)

3
Part III: Practice

Best practices, migration guides, and a capstone project to tie it all together

💡
Key Insight

Every bridge book ends with a capstone project — a real, complete application. The C# book builds a CLI weather tool. The Python book builds a task manager. You do not just learn concepts — you build something real.
