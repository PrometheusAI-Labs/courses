Как стратегия реагирует на события

85 минут · разберём обработчик события, подписку и безопасный прогрев индикаторов.

1. Датчик дыма, а не дежурный с секундомером 10 минут

🔔

Событийная модель

Стратегия подписывается один раз. Движок сам вызывает обработчик, когда появляется бар.

🔁

Постоянный опрос

Polling loop тратит работу на вопрос «есть ли что-нибудь?» и усложняет время обработки.

💡
Lifecycle — это договор

На старте стратегия объявляет, что ей нужно; затем обработчики отвечают только на доставленные события.

📣

Подписка

Говорит движку, какой тип события нужно доставлять стратегии.

⏳

Прогрев

Прогрев не даёт принимать решение до готовности индикаторов.

🚪

Ранний выход

Если готовности нет, обработчик безопасно прекращает текущую реакцию.

3. Контракт стратегии в реальном коде 20 минут

КОД ПРОЕКТА 
    def on_start(self) -> None:
        self.register_indicator_for_bars(self.config.bar_type, self.fast_ema)
        self.register_indicator_for_bars(self.config.bar_type, self.slow_ema)
        self.subscribe_bars(self.config.bar_type)

    def on_bar(self, _bar: Bar) -> None:
        if not self.indicators_initialized():
            return
ПРОСТЫМИ СЛОВАМИ

При запуске стратегии начинается настройка её реакций.

Два индикатора привязываются к нужному типу баров.

Стратегия просит движок присылать эти бары.

Когда бар приходит, движок вызывает обработчик.

Если индикаторы ещё не готовы, текущий бар не используется для решения.

🔎
Две разные тишины

«on_bar не вызван» указывает на доставку; «вызван и вернулся» указывает на readiness-gate. Не смешивайте эти диагнозы.

4. Лабораторная работа: «Тишина в обработчике» 25 минут

A

Обработчик не вызван

Доказательство: нет входа в on_bar. Проверьте подписку и совпадение bar_type.

B

Обработчик сразу завершает работу

Доказательство: вход есть, торгового решения нет. Проверьте состояние и прогрев индикаторов.

C

Не тот поток

Доказательство: публикуется другой тип бара. Сравните конфигурацию подписки и входные данные.

⛔
Сначала наблюдение, потом изменение

Запрос AI должен требовать доказать, какой из трёх случаев произошёл, и только затем предлагать минимальное исправление.
