Стратегия как проверяемая гипотеза

EMA cross здесь — прозрачный объект исследования: правило можно трассировать, опровергнуть и ограничить.

Термостат, а не оракул

Термостат сравнивает наблюдение с порогом и действует по правилу; он не предсказывает погоду. Так же стратегия реагирует на данные и состояние.

≈

Наблюдение

Fast и slow EMA описывают прошлые значения по-разному.

◇

Состояние

Flat / short меняют допустимую ветвь.

→

Намерение

`buy()` выражает решение стратегии, но ещё не доказывает fill.

⊘

Опровержение

Гипотеза заранее говорит, какое наблюдение заставит её отвергнуть.

💡
Сигнал не равен исполнению

Между условием и сделкой остаются модель заявок, ликвидность, задержка, комиссии и проскальзывание.

Читаем реальный обработчик

`on_bar` сначала проверяет готовность, затем выбирает действие по сигналу и состоянию.

CODE
    def on_bar(self, _bar: Bar) -> None:
        if not self.indicators_initialized():
            return

        if self.fast_ema.value >= self.slow_ema.value:
            if self.portfolio.is_net_flat(self.config.instrument_id):
                self.buy()
            elif self.portfolio.is_net_short(self.config.instrument_id):
                self.close_all_positions(self.config.instrument_id)
                self.buy()
ПО-РУССКИ

Когда приходит новый бар, запустить эту логику.

Если индикаторы ещё не готовы, ничего не делать.

Проверить условие: fast EMA не ниже slow EMA.

Если позиции нет, вызвать `buy()`.

Если позиция short, сначала закрыть все позиции по инструменту.

После закрытия вызвать `buy()` — это намерение, не доказанный fill.

⚠
Не дописывайте поведение мысленно

Фрагмент показывает только bullish-ветвь. Он не даёт права угадывать ветвь fast EMA < slow EMA или детали исполнения.

Лабораторная работа: трасса четырёх баров

Для каждого бара получите «готовность, fast/slow, состояние». Запишите только ожидаемое намерение, а fill, latency, fees и slippage оставьте как неизвестные.

1
Bar A · not ready

2
Bar B · fast ≥ slow · flat

Ожидается вызов `buy()`.

3
Bar C · fast ≥ slow · short

Ожидается `close_all_positions()`, затем `buy()`.

4
Bar D · fast < slow

Этот фрагмент не показывает действие: вывод ограничен.

Что результат доказывает — и чего не доказывает

Бэктест — ценный краш-тест модели. Он показывает поведение в заданных условиях, а не гарантирует реальные дороги.

Краш-тест полезен именно своими границами

Детерминированность помогает повторить наблюдение. Но реальная площадка может отличаться ликвидностью, задержкой, очередью и отказами.

Лестница доказательств: каждый шаг — новая проверка

Gate не выдаёт сертификат навсегда; он отвечает только на вопрос о следующем ограниченном этапе.

1
Backtest

Исторические данные + модель. Артефакты: catalog, config, code, results.

2
Forward

Правила фиксированы до новых наблюдений; нет подбора по уже увиденному периоду.

3
Shadow

Система получает живые события, но не отправляет реальные заявки.

4
Canary

Минимально ограниченный реальный риск со stop conditions.

5
Live scope

Только подтверждённые лимиты, мониторинг и reconciliation; не безусловная готовность.

BACKTESTGO только к следующей проверке, не к капиталу.
MISSINGНет forward/shadow/reconciliation — это пробел, а не «почти готово».
NO-GOКорректное решение, когда gate не подтверждён.
