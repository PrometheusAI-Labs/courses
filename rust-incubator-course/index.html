Что такое Rust Incubator?

Пошаговый путь изучения Rust — от основ языка до бэкенд-разработки

Зачем нужен Rust Incubator?

Rust — это язык, который даёт тебе мощь C++ без его ловушек. Rust Incubator — это жёсткий, но чёткий маршрут обучения от самых основ до бэкенд-разработки.

Представьте инкубатор как парник для растений. Проект создаёт идеальные условия для роста ваших навыков Rust: структурированные шаги, практические задания и постепенное усложнение.

📚
Как это работает?

Каждый шаг содержит теорию, примеры кода и задание. Компилятор Rust — ваш строгий наставник: он не пропустит ни одной ошибки.

02

Владение и память

Как Rust управляет памятью без сборщика мусора

📚
Метафора: библиотечная карточка

Каждая книга имеет ровно одного держателя. Хочешь прочитать — возьми на время (borrow). Хочешь передать — верни и отдай карточку другому (move).

Почему это важно

Rust не имеет сборщика мусора (GC). Вместо этого он использует систему ownership, проверяемую на этапе компиляции. Это означает: никаких утечек памяти, никаких гонок данных — и всё это без runtime-затрат.

Три правила владения

1
Один владелец

У каждого значения в Rust есть ровно один владелец (owner).

2
Автоматическое уничтожение

Когда владелец выходит из области видимости — значение уничтожается (Drop).

3
Move или Borrow

Значение можно передать (move) или одолжить (borrow) — но не одновременно изменяемо из двух мест.

Move vs Borrow — код из проекта

Rust fn main() { let s1 = String::from("hi"); let s2 = s1; println!("{}", s2); }
Построчно по-русски
Создаём строку "hi" и кладём в переменную s1
Передаём владение строкой из s1 в s2 (move). Теперь s1 больше недоступна!
Печатаем s2 — это работает, потому что s2 теперь владелец
(после этой строки s2 выходит из области видимости, память освобождается)
Rust fn main() { let s1 = String::from("hi"); print_str(&s1); println!("{}", s1); } fn print_str(s: &String) { println!("{}", s); }
Построчно по-русски
Создаём строку "hi"
Передаём ссылку (&s1) — одалживаем, не отдаём владение
s1 всё ещё жива! Можно использовать дальше
Функция принимает ссылку (&String) — читает, но не владеет
Печатает строку через ссылку

03

Ключевые концепции

Default, Clone, Copy, Box, Rc, Cell — инструменты для управления данными

Зачем нужны эти концепции

В модуле 2 мы узнали, что у каждого значения один владелец. Но что, если нужно скопировать данные? Или иметь несколько владельцев? Или менять данные через неизменяемую ссылку? Для этого в Rust есть набор трейтов и умных указателей.

Представьте набор инструментов электрика. Каждый инструмент решает конкретную задачу: отвёрткой закручивают шурупы, мультиметром измеряют напряжение, кусачками режут провода. Нельзя закрутить шуруп молотком — нужно знать, когда какой инструмент брать. Точно так же каждый трейт и умный указатель в Rust предназначен для своей задачи.

📚
Зачем столько инструментов?

Rust не использует сборщик мусора. Вместо этого он даёт вам точные инструменты для управления памятью. Каждый трейт — это договор между вами и компилятором: «Я обещаю, что мой тип умеет делать вот это».

Copy vs Clone — код из проекта

Посмотрим на реальный код из проекта Rust Incubator. Две структуры — Point и Polyline — демонстрируют разницу между Copy и Clone.

1_concepts/1_1_default_clone_copy/src/main.rs 
// Определяем структуру Point
#[derive(Debug, Copy, Clone, Default, PartialEq)]
struct Point {
    x: f64,
    y: f64,
}

// Определяем структуру Polyline
#[derive(Debug, Clone)]
struct Polyline {
    points: Vec<Point>,
}
НА РУССКОМ

Определяем структуру Point с двумя координатами

#[derive(...)] — автоматически реализует трейты: Copy (побитовое копирование), Clone (глубокое копирование), Default (значение по умолчанию: x = 0.0, y = 0.0)

x и y — числа с плавающей точкой (f64). Простые типы фиксированного размера — значит Copy возможен

Polyline — набор точек, образующих ломаную линию

Vec<Point> хранится в куче (heap) — значит Copy невозможен, только Clone. Копирование Vec означает выделение новой памяти и копирование всех элементов

Семейство умных указателей

Когда обычного владения недостаточно, Rust предлагает умные указатели. Каждый решает свою задачу — как инструмент в наборе электрика.

📦
Box<T>

Кладёт данные в кучу (heap). Один владелец, как обычно. Нужен для рекурсивных типов или больших данных, которые дорого копировать на стеке.

🔗
Rc<T>

Счётчик ссылок. Несколько владельцев одних данных. Только для одного потока! Когда счётчик достигает нуля, данные уничтожаются.

⚡
Arc<T>

Атомарный Rc. Как Rc, но безопасен для многопоточности. Дороже по производительности из-за атомарных операций.

🔓
Cell<T> / RefCell<T>

Внутренняя мутабельность. Позволяют менять данные через &T (неизменяемую ссылку). Проверка заимствований — в runtime, не в compile time.

Send и Sync — безопасность потоков

Rust проверяет безопасность многопоточного кода на этапе компиляции. Два маркерных трейта — Send и Sync — определяют, какие типы можно использовать в многопоточном контексте.

1_concepts/1_8_thread_safety/src/main.rs 
pub struct SyncAndSend<T> {
    data: Arc<Mutex<T>>,
    _phantom: PhantomData<T>,
}
НА РУССКОМ

SyncAndSend<T> — тип, безопасный для передачи (Send) и разделения (Sync) между потоками

Arc<Mutex<T>> — атомарный счётчик ссылок + блокировка для эксклюзивного доступа к данным. Arc даёт общее владение между потоками, Mutex даёт безопасную мутабельность

PhantomData<T> — фантомный тип, сообщает компилятору дополнительную информацию о T. Не занимает памяти, но важен для корректности проверок

💡
Правило большого пальца

Если данные живут в одном потоке — используйте Rc<RefCell<T>>. Если данные делятся между потоками — используйте Arc<Mutex<T>>. Это два главных паттерна общего владения в Rust.

04

Идиомы и паттерны

Как писать код, который Rust-сообщество назовёт идиоматичным

Зачем нужны идиомы

Представьте правила дорожного движения. Технически машина может ехать по встречке — но так никто не делает. Идиомы — это правила, по которым пишут код профессионалы.

Компилятор Rust гарантирует безопасность памяти, но не гарантирует качество дизайна. Идиомы — это проверенные паттерны, которые делают код надёжнее, читаемее и удобнее в использовании.

Хороший API трудно использовать неправильно. Идиоматичный Rust-код превращает потенциальные ошибки программиста в ошибки компиляции — задолго до того, как код попадёт в продакшн.

Newtype — типы вместо ошибок

Начнём с реального бага. Посмотрите на структуру Post и функцию repost — видите проблему?

Rust — версия с багом 
#[derive(Clone)]
struct Post {
    id: u64,
    user_id: u64,
    title: String,
    body: String,
}

fn repost(post: &Post, new_author_id: u64) -> Post {
    let mut new_post = post.clone();
    new_post.id = new_author_id;  // Oops!
    new_post
}
Что тут происходит
Структура Post: поля id и user_id — оба u64. Компилятор не видит разницы!
Поля title и body — оба String. Тоже легко перепутать.
Функция repost должна обновить user_id...
...но мы случайно записали new_author_id в поле id. Баг! И компилятор молчит.

Решение — паттерн Newtype. Обернём каждое значение в свой тип:

Rust — исправленная версия 
mod post {
    #[derive(Clone, Debug, PartialEq, Eq)]
    pub struct Id(u64);

    #[derive(Clone, Debug, PartialEq, Eq)]
    pub struct Title(String);
}

mod user {
    #[derive(Clone, Debug, PartialEq, Eq)]
    pub struct Id(u64);
}
Что изменилось
Создаём отдельные типы post::Id и user::Id
Оба хранят u64 внутри, но компилятор считает их разными типами
Теперь перепутать post::Id и user::Id — ошибка компиляции!
Zero-cost: в runtime никаких накладных расходов

Typestates — машина состояний в типах

А что если нужно гарантировать порядок операций? Например, пост проходит модерацию: его нельзя удалить до публикации и нельзя опубликовать повторно. Паттерн Typestates кодирует эти правила прямо в системе типов.

N
New — новый пост

Только что создан. Единственное доступное действие — publish(), которое отправит пост на модерацию.

U
Unmoderated — на модерации

Ожидает решения модератора. Доступны два действия: allow() — одобрить, deny() — отклонить.

P
Published — опубликован

Пост доступен читателям. Единственное доступное действие — delete().

D
Deleted — удалён

Финальное состояние. Никаких действий больше не доступно.

Вот как это выглядит в коде:

Rust 
impl Post<New> {
    pub fn publish(self) -> Post<Unmoderated> {
        // ...
    }
}

impl Post<Unmoderated> {
    pub fn allow(self) -> Post<Published> {
        // ...
    }
    pub fn deny(self) -> Post<Deleted> {
        // ...
    }
}

impl Post<Published> {
    pub fn delete(self) -> Post<Deleted> {
        // ...
    }
}
Построчный разбор
publish() доступен ТОЛЬКО для Post<New>. Нельзя опубликовать уже опубликованный пост!
allow() и deny() — только для Post<Unmoderated>
Каждый переход потребляет (self) старое состояние и создаёт новое
Невозможные переходы — ошибка компиляции. Не runtime, а на этапе сборки!
💡
Zero-cost абстракции в действии

Паттерн Newtype не стоит ничего в runtime — это чисто компиляторная абстракция. Но он предотвращает целый класс багов: перепутанные ID, невалидные email-адреса, неправильные единицы измерения. Чем больше семантики в типах — тем меньше багов в коде.

Serde — король сериализации

Serde — самая скачиваемая библиотека Rust. Одна аннотация #[derive(Serialize, Deserialize)] — и ваша структура умеет превращаться в JSON, TOML, YAML, MessagePack и десятки других форматов.

Rust use serde::{Serialize, Deserialize}; #[derive(Debug, Serialize, Deserialize)] struct Config { host: String, port: u16, debug: bool, }
Построчно по-русски
Подключаем трейты Serialize и Deserialize из библиотеки serde
derive автоматически генерирует код для сериализации на этапе компиляции
Структура Config с тремя полями: host (строка), port (число), debug (флаг)
Теперь Config умеет превращаться в JSON: {"host":"...", "port":8080, "debug":true}
И обратно: из строки JSON можно восстановить структуру Config

Итоговый проект этапа экосистемы — настоящая CLI-утилита для обработки JPEG-изображений: удаление метаданных и минимизация размера файла. Здесь сходятся все изученные темы: CLI-парсинг, конфигурация, параллелизм, логирование.

1
Ввод из разных источников

Принимает файлы и URL через CLI-аргументы, stdin или файл-список. Используются библиотеки clap и reqwest.

2
Параллельная обработка

Несколько изображений обрабатываются одновременно с помощью rayon или tokio — без блокировки основного потока.

3
Настраиваемое качество

Параметр качества JPEG на выходе задается пользователем. Баланс между размером файла и визуальным качеством.

4
Каскадная конфигурация

Настройки загружаются из файла конфигурации, переменных окружения и CLI-аргументов — с приоритетом в этом порядке.

5
Управляемое логирование

Поддержка RUST_LOG для управления уровнями логирования: от тихого режима до подробной отладки через tracing.

⚡
Async — это не магия

Async в Rust — это кооперативная многозадачность: каждая задача сама решает, когда уступить управление. В отличие от потоков ОС, переключение между Future практически бесплатно. Поэтому Tokio может обрабатывать сотни тысяч соединений на одном сервере.

Базы данных, HTTP-серверы и GraphQL API — финальный рубеж

📚
Метафора: диспетчерская башня аэропорта

Бэкенд — это центр управления: принимает запросы (самолёты), проверяет их, направляет к нужным данным (терминалам) и отправляет ответы обратно. Каждый компонент системы — HTTP-сервер, GraphQL-резолвер, база данных — это отдельная служба аэропорта, работающая слаженно.

Финальный проект — GraphQL API сервер

Кульминация всего курса. Финальный проект объединяет всё, что вы изучили: систему типов, async/await, работу с базой данных и HTTP. Вот требования:

Модель данных

User с полями id, name и список friends (другие User). Рекурсивная структура — друзья тоже имеют друзей.

2
Аутентификация по паролю

Пользователь вводит логин и пароль, сервер возвращает токен авторизации. Пароли хранятся в хешированном виде.

Мутация для создания нового пользователя с именем и паролем. Валидация входных данных.

Запрос пользователя со всеми друзьями (и друзьями друзей) — требует авторизации. Поддержка вложенных запросов.

Добавление и удаление друзей

Мутации для управления списком друзей — требуют авторизации. Только авторизованный пользователь может изменять свой список.

Почему Rust для бэкенда

Rust сочетает три качества, которые редко встречаются вместе в одном языке.

⚡
Производительность

Скорость C/C++ без сборщика мусора. Предсказуемая латентность, нет пауз GC. Серверы на Rust обрабатывают миллионы запросов с минимальным потреблением памяти.

🔒
Безопасность

Никаких data races, null pointer dereference или buffer overflow. Компилятор гарантирует корректность на этапе сборки, а не в продакшене.

💫
Надёжность

Если скомпилировалось — с высокой вероятностью работает корректно. Паттерн Result<T, E> вместо исключений. Ошибки обрабатываются явно, а не прячутся в стеке вызовов.

⚠️
Важно: depth limiting

GraphQL решает проблему REST — over-fetching и under-fetching. Клиент сам описывает, какие именно данные ему нужны. Но это создаёт новую проблему: вложенные запросы могут убить базу данных. Запрос friends { friends { friends { ... } } } генерирует экспоненциальное количество SQL-запросов. Поэтому в задании предлагают реализовать depth limiting — ограничение глубины вложенности запросов.
